# QBF formulation for card-based AND protocols with mixed encoding

This repository contains the code and data for the QBF part of the paper

> Saeki Koizumi, Xiao-Nan Lu, and Hidetomo Nabeshima.
> *Card-Based Protocols with Mixed Encoding: Computable Functions and the Minimum Number of Cards.*

It generates the quantified Boolean formulas of Section 4.2 ("Formal verification by QBF"), solves them with DepQBF and CAQE, and reproduces Table 2 and the run with two random cuts reported in Section 4.2. Section, table, and proposition numbers refer to the manuscript.

## Contents

| Path | Description |
|---|---|
| `qbf_gen.py` | Generator of formulas (1) and (2) in QDIMACS format |
| `run.py` | Generates the instances of Table 2, runs the solvers, and writes `results/results.md` |
| `instances/` | The seven instances of Table 2, and `n4_k2_rc_sec.qdimacs` for the run with two random cuts |
| `outputs/depqbf/`, `outputs/caqe/` | Raw solver outputs (the run with two random cuts: DepQBF only) |
| `results/results.md` | Truth values, formula sizes, and times of Table 2; protocols read off from the true formulas |
| `check_protocols.py` | Independent enumeration of a decoded protocol, using exact rational probabilities |
| `witnesses/positive_protocols.json` | Three protocols decoded from the stored positive DepQBF assignments, with uniform shuffle probabilities |
| `results/witness_checks.json` | Correctness, security verdicts, and exact observation probabilities for these protocols |
| `SHA256SUMS` | SHA-256 checksums of the package files, excluding the checksum file itself |

## Requirements

- Python 3.8 or later (standard library only)
- [DepQBF](https://github.com/lonsing/depqbf) 6.03, e.g. `brew install depqbf` on macOS
- [CAQE](https://github.com/ltentrup/caqe) 4.0.1 (optional, used as a second solver). We built commit `643a2e9` with `cargo build --release --no-default-features`, i.e., without the optional jemalloc allocator.

## Usage

Reproduce Table 2:

```
python3 run.py                           # DepQBF, and CAQE if `caqe` is on the PATH
python3 run.py --caqe /path/to/caqe      # CAQE elsewhere
python3 run.py --no-caqe                 # DepQBF only
```

Reproduce the run with two random cuts in Section 4.2 (about eight minutes):

```
python3 qbf_gen.py --cards 4 --shuffles rc --blocks 2 -o instances/n4_k2_rc_sec.qdimacs
depqbf --qdo --no-dynamic-nenofex instances/n4_k2_rc_sec.qdimacs
```

Generate a single formula:

```
python3 qbf_gen.py --cards 3 --shuffles arbitrary                 # formula (1)
python3 qbf_gen.py --cards 3 --shuffles arbitrary --no-security   # formula (2)
```

| Option | Values |
|---|---|
| `--cards` | number $n$ of working cards. `3`: input sequence $(a,b,\bar b)$; `4`: $(♣,a,b,\bar b)$ |
| `--shuffles` | class of the sets $\Pi_\ell$. `transposition`: $\lbrace\mathrm{id},\tau\rbrace$ for a transposition $\tau$; `rbc`: $\lbrace\mathrm{id},\tau_1\cdots\tau_{n/2}\rbrace$ for pairwise disjoint transpositions (random bisection cuts); `closed`: all subgroups of $S_n$ (closed shuffles); `rc`: cyclic groups generated by an $n$-cycle (random cuts); `arbitrary`: any nonempty subset of $S_n$ |
| `--blocks` | number $k$ of shuffles, each preceded by a rearrangement (default 1) |
| `--no-security` | formula (2), correctness only; the default is formula (1) |

DepQBF is run with `--qdo --no-dynamic-nenofex`: `--qdo` prints the values of the outermost existential variables, i.e., the protocol, and DepQBF requires `--no-dynamic-nenofex` together with it. CAQE is run with `--qdo`. Both solvers exit with code 10 for a true formula and 20 for a false one.

## Independent checking of positive protocols

Run the checker without a solver:

```
python3 check_protocols.py
python3 check_protocols.py --json results/witness_checks.json
```

The checker reads `witnesses/positive_protocols.json` and uses only the Python standard library. It does not import the QBF generator or inspect QBF clauses. For all four inputs and every combination of shuffle outcomes, it applies the listed permutations, checks that the output is AND, and computes the exact distribution of the final observation with rational arithmetic. All cards are face down until the final turn, so this observation determines the visible sequence trace. The output rule must select an unturned card.

The JSON file records permutations and positions using the paper's 1-based convention, as well as the source solver-output filenames and their SHA-256 hashes. The protocols were decoded from the stored outer existential assignments; the corresponding generated instances were checked to match the supplied instances byte for byte before decoding. The QBF does not specify probabilities, so each listed shuffle is realized uniformly. The checker verifies this particular realization.

The correctness-only three-card witness is correct but fails both security checks. The random-bisection-cut and closed-shuffle witnesses are correct and perfectly secure: each observation has probability 1/2 under every input. `PASS` means that all three verdicts agree with the expected verdicts in the JSON file; it does not mean that every listed protocol is secure. A mismatching verdict exits with status 1, and invalid protocol data exits with status 2.

These checks concern the decoded positive protocols. They are not proof certificates for false QBF instances and do not verify the unrestricted mathematical lower bounds.

## The formulation

Alice's input $a$ is a single-card commitment, and Bob's input $b$ is a two-card commitment. For $\ell=1,\dots,k$, a protocol of the class applies a rearrangement $(\mathsf{perm},\pi_\ell)$ followed by a shuffle $(\mathsf{shuffle},\Pi_\ell,\mathcal{F}_\ell)$. After the last shuffle, it turns the cards in a fixed set $T$ with $|T|\le n-1$, and outputs the card at a position $R(T,\boldsymbol{v})\notin T$ that depends on the symbols $\boldsymbol{v}$ of the turned cards. The generator encodes $f(a,b)=a\wedge b$. The formulas are

$$
\begin{aligned}
&\exists\mathcal{P}\ \forall a,b,\mathcal{O}\ \exists\mathcal{X}\ \forall a',b'\ \exists\mathcal{O}',\mathcal{X}':\\
&\quad\mathrm{Protocol}(\mathcal{P})\wedge\bigl[\mathrm{Valid}(\mathcal{O})\rightarrow\bigl(\mathrm{Trace}(a,b,\mathcal{O},\mathcal{X})\wedge\mathrm{Correct}(a,b,\mathcal{X})\\
&\qquad\wedge\mathrm{Valid}(\mathcal{O}')\wedge\mathrm{Trace}(a',b',\mathcal{O}',\mathcal{X}')\wedge\mathrm{Same}(\mathcal{X},\mathcal{X}')\bigr)\bigr],
\end{aligned}
\tag{1}
$$

$$
\exists\mathcal{P}\ \forall a,b,\mathcal{O}\ \exists\mathcal{X}:\ \mathrm{Protocol}(\mathcal{P})\wedge\bigl[\mathrm{Valid}(\mathcal{O})\rightarrow\bigl(\mathrm{Trace}(a,b,\mathcal{O},\mathcal{X})\wedge\mathrm{Correct}(a,b,\mathcal{X})\bigr)\bigr],
\tag{2}
$$

where $\mathcal{P}$ is the tuple of protocol variables, $\mathcal{O}=(\mathcal{O}_1,\dots,\mathcal{O}_k)$ the outcomes of the shuffles, each encoded in binary, and $\mathcal{X}$ the variables of an execution. The last three conjuncts of (1) express possibilistic security.

The variables in `qbf_gen.py` and their names in the paper, in the order of the quantifier prefix:

| Quantifier | Code | Paper |
|---|---|---|
| $\exists$ | `s[l][i]`, `m[l][i]`, `c[l][S]`, `u[T]`, `r[T, v][p]` | $s_{\ell,\pi}$, $m_{\ell,\pi}$, $c_{\ell,\Pi}$, $u_T$, $r_{T,\boldsymbol{v},i}$ (the tuple $\mathcal{P}$) |
| $\forall$ | `a`, `b`, `F[l]` | $a$, $b$, and the bits of $\mathcal{O}_\ell$ |
| $\exists$ | `x0[j]`, `y[l][j]`, `x[l][j]`, `z` | $x^{(0)}_j$, $y^{(\ell)}_j$, $x^{(\ell)}_j$, $z$ (the tuple $\mathcal{X}$) |
| $\exists$ | `e[l][i]`, `w[l]`, `g` | the auxiliary variables of the CNF translation |
| $\forall$ | `a2`, `b2` | $a'$, $b'$ |
| $\exists$ | `e2[l][i]` and the card variables of the second execution | $e'_{\ell,\pi}$ and $\mathcal{X}'$ |

By Proposition 4.6, formula (1) is true if and only if some protocol of the class computes AND with possibilistic security. Since every perfectly secure protocol is possibilistically secure, a false formula rules out secure protocols of the class, for any probability distributions of the shuffles. A true formula yields a protocol with possibilistic security, and its perfect security still has to be verified, e.g., by a KWH-tree.

**Conventions.** Card values are $0={}$♣ and $1={}$♡. Positions are 1-based in all output. A permutation $\pi$ moves the card at position $j$ to position $\pi(j)$, and is printed in cycle notation.

## Results

`results/results.md` is the output of `run.py` on a MacBook Pro (Apple M1, 8 cores, 16 GB, macOS 15.7). Table 2 of the paper shows its DepQBF columns, with times below 0.1 s shown as <0.1. Both solvers agree on all truth values.

The run with two random cuts (`n4_k2_rc_sec`, 379 variables, 3695 clauses) gives false, in agreement with Proposition 4.5. DepQBF took 489 s on the same machine, compared with 1.3 s for one random cut. Its output is `outputs/depqbf/n4_k2_rc_sec.txt`.
